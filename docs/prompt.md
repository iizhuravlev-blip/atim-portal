# Задача: центральная страница «АТИМ Управление» с виджетами модулей

## Главная идея
«АТИМ Управление» — платформа ООО «АТИМ» и ООО «АТИМ Разработка» из нескольких модулей
(СЭД, CRM, групповой бот, ТИМ.Тендер, дальше — маркетинг и финансы). Центральная страница —
это **точка входа**: сотрудник открывает её утром и сразу видит, что требует внимания во всех
модулях, а одним кликом переходит в нужный модуль к нужной записи.

Страница не дублирует модули и не хранит их данные. Каждый модуль отдаёт свой виджет по общему
контракту [`docs/widgets.md`](widgets.md), а портал собирает виджеты на одном экране.

## Виджеты

### Обязательные
1. **Документооборот** (СЭД, `docs.mail`)
   - Главное число — новые письма в очереди «Почта на регистрацию», разбивка АТ / АР.
   - Дополнительно — «На подпись» (для подписантов) и «Мои поручения: просрочено / сегодня».
   - Строки — последние 5 писем: отправитель (контрагент из справочника), тема, время.
   - Видимость — по ролям СЭД: делопроизводитель видит очередь своих организаций, исполнитель —
     только свои поручения.
2. **Mind CRM** (CRM, `crm.tasks`)
   - Главное число — мои открытые задачи в CRM, отдельно просроченные и на сегодня.
   - Строки — ближайшие задачи: название, компания, срок, ссылка на узел карты.
   - Дополнительно — сделки в работе и их сумма.
3. **Маркетинг** — заглушка (`status: "stub"`, «Модуль в разработке»).
4. **Финансы** — заглушка (`status: "stub"`).
5. **Календарь** (групповой бот, `bot.today`)
   - Встречи сотрудника на сегодня из Google Календаря команды: время, название, место или
     ссылка ВКС, участники.
   - «Мои» встречи бот определяет так же, как для утреннего плана (`event_people` в
     `bot/digest.py`): автор, сотрудники в копии приглашения, участники.
   - Подсветка: идёт сейчас / следующая через N минут. Дополнительно — число встреч завтра.
6. **Задачи** (сводный, `bot.tasks` + `docs.tasks`)
   - Все мои задачи из всех источников в одном списке:
     - задачи из бота (Google Tasks через `assignments`, включая поставленные из CRM — у них
       пометка «CRM» и ссылка на карту);
     - поручения СЭД (резолюции по документам — ссылка на документ).
   - Сортировка по сроку, просроченные сверху. Задача из CRM не показывается дважды
     (в боте она связана с узлом через `crm_links`).
   - «✅ Выполнено» прямо из виджета — только если модуль-источник это поддерживает
     (ссылка-действие в `actions`; выполнение задачи бота идёт с той же проверкой автором,
     что и в Telegram).

### Предлагаемые (покажи мне, какие делать в первой версии)
7. **Тендеры** (ТИМ.Тендер): новые тендеры за сутки по подпискам, ближайшие дедлайны подачи.
8. **Договоры** (СЭД): истекают в 30 дней, акты не подписаны контрагентом дольше N дней.
9. **Переговорная**: свободна или занята сейчас, следующая встреча в ней.
10. **Быстрый ввод**: строка «Позвонить Иванову завтра в 15:00 @petrov» → задача или встреча
    через парсер бота, с карточкой подтверждения прямо на странице.

## Интерфейс
- Сетка карточек-виджетов: на компьютере 3 колонки, на планшете 2, на телефоне 1.
- Карточка: заголовок модуля (ссылка), главное число, разбивка, до 5 строк, кнопки. Цвет числа —
  по `tone`. Пустое состояние спокойное («Новых писем нет»), а не красное.
- Сотрудник может менять порядок виджетов, скрывать их и возвращать. Раскладка хранится на
  сервере портала для каждого сотрудника.
- Шапка: логотип «АТИМ Управление», переключатель модулей (тот же, что в СЭД и CRM), имя
  сотрудника, выбор организации (Все / АТ / АР), выход.
- Автообновление раз в 60 секунд без перезагрузки страницы, плюс кнопка «Обновить».
- Стиль — как у СЭД и atim.tech: фиолетово-синий (`#8B5CF6 → #6366F1`, `#C4B5FD`, `#22D3EE`),
  светлая и тёмная темы.

## Архитектура
- Backend: Python (FastAPI), как у СЭД. Портал вызывает `/api/v1/widget` модулей
  **параллельно**, с таймаутом 3 с на модуль и кэшем 60 с на сотрудника. Отказ одного модуля
  не ломает страницу.
- Своих бизнес-данных у портала нет. Хранит только настройки: список виджетов и их источники,
  раскладки сотрудников, токены модулей.
- **Вход — единый, через СЭД** (ядро): своих паролей у портала нет. Предложи механизм единого
  входа для поддоменов `*.atimlab.ru` (портал, CRM, СЭД): например, СЭД выдаёт подписанный
  короткоживущий токен по перенаправлению, или общая cookie сессии на `.atimlab.ru`.
  Согласуй со мной до кода — им будет пользоваться и CRM.
- Размещение: сервер `mind`, отдельный docker-compose проект в сети `wisemapping_frontend`,
  HTTPS через Caddy проекта `/opt/wisemapping` (по образцу `atim-docs/service/DEPLOY.md`).
  Адрес — предложи (например `upr.atimlab.ru`; или корневая страница, а СЭД остаётся на `docs.`).

## Что нужно доработать в модулях
Каждая доработка делается в репозитории своего модуля, отдельной веткой, с тестами:
- **СЭД**: `GET /api/v1/widget` (`docs.mail`, `docs.tasks`, позже `docs.contracts`), токен портала,
  механизм единого входа.
- **Групповой бот**: `GET /api/v1/widget` (`bot.today`, `bot.tasks`) на существующем aiohttp-
  сервере. Логику переиспользовать: `events_between`, `event_people`, `open_assignments`.
  В Caddy бота путь открыть только для IP сервера `mind`.
- **CRM**: виджет `crm.tasks` уже описан в `atim-crm/docs/prompt.md` (часть 3).
- **ТИМ.Тендер**: виджет `tenders.new` (если войдёт в первую версию).

## Критерии готовности
- Сотрудник входит один раз и попадает на портал, СЭД и CRM без повторного ввода пароля.
- На странице видны новые письма, мои встречи сегодня и все мои задачи; клик ведёт к
  конкретному письму, встрече или задаче в модуле.
- Если бот недоступен, остальные виджеты работают, а «Календарь» показывает
  «Нет связи, данные на 09:10».
- Делопроизводитель АТ не видит очередь писем АР, если у него нет доступа к АР.
- Страница открывается быстрее чем за 2 секунды и удобна на телефоне.

Прежде чем писать код, изучи модули из таблицы, задай уточняющие вопросы, предложи архитектуру
и план и только после этого начинай с шага 0.
